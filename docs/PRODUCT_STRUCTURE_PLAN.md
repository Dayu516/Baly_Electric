# 品項結構化計畫

**目標：** 把品項從「扁平文字」升級為「結構化工業料件」，支援組合品/可替換件/規格查詢。
**原則：** 不急、穩、一族一族做。80% 通用，20% 特例擴充。
**不做：** 組裝單、轉換單、POS 自動扣料（等樣板跑順再評估）。

---

## 0. 家族分級原則

> 每個家族開始前先判斷級別，不要為少數複雜家族把全系統做重。

| 級別 | 定義 | 需要什麼 | 佔比 | 範例 |
|------|------|---------|------|------|
| **Level 1：一般品項** | 不可再拆、規格簡單 | 分類 + 品牌 + 型號 + 別名 | ~60% | 工具、耗材、端子、線槽、膠帶 |
| **Level 2：規格型品項** | 有結構化規格需求，但無 BOM | 屬性模板 + 結構化欄位 + 條件搜尋 | ~30% | 電纜、開關、指示燈、繼電器、計時器 |
| **Level 3：結構型品項** | 有組成關係、可拆裝、可互換 | 框架固有屬性 + SKU 變動屬性 + BOM + 提示 | ~10% | 接觸器/電磁開關/積熱/線圈 |

### 分級決策規則
- **Level 1：** 沒有複雜規格、沒有組合關係 → 直接匯入，不做模板
- **Level 2：** 有多個規格欄位影響選型（電壓/電流/尺寸...）→ 做屬性模板，不做 BOM
- **Level 3：** 有零件可拆裝、有組合品、有框架概念 → 做完整結構化 + BOM

### 匯入策略對應
- **Level 1：** 清洗後直接匯入（品名+品牌+型號就夠）
- **Level 2：** 清洗時按模板結構化，匯入帶屬性
- **Level 3：** 先定完模板+BOM 關係，再整理匯入

## 1. 品項型態定義

所有 SKU 新增一個結構化欄位 `item_type`：

| 型態 | 說明 | 範例 |
|------|------|------|
| `finished` | 成品 — 直接銷售的最終產品 | S-P11 AC220V（接觸器成品） |
| `assembly` | 組合品 — 由多個成品/零件組成 | MSO-P11 220V TH-12(3.3A) |
| `accessory` | 配件 — 搭配使用但不是組成件 | 接觸器安裝底板 |
| `component` | 可替換零件 — 可拆裝、可互換 | 線圈 AC110V、線圈 AC220V |

預設值：`finished`（現有 12,000 筆品項不受影響）。

## 2. 分類結構（接觸器家族樣板）

利用現有的分類樹（已支援父子結構）：

```
接觸器類（家族根節點）
├── 裸接觸器        — S-P11, S-P12, SC-N2... (finished)
├── 積熱電驛        — TH-12, TH-18... (finished)
├── 電磁開關        — MSO-P11, MSO-T11... (assembly)
└── 接觸器零件      — 線圈 AC110V, 線圈 AC220V... (component)
```

### 注意事項
- 接觸器 和 電磁開關 不是平行分類，電磁開關 = 接觸器 + 積熱的組合品
- 分類決定屬性模板（哪些欄位該填）
- 零件（如線圈）獨立分類，因為它有自己的庫存和進貨

## 3. 屬性模板（利用現有 category_attribute_templates）

### 設計原則：框架固定屬性 vs SKU 變動屬性

接觸器的核心真相是**框架型號**，不是個別 SKU。

```
S-P11 = 框架型號，代表：3 主接點、單接點 20A、1a 輔助接點
S-P12 = 框架型號，代表：4 主接點、單接點 20A、1a1b 輔助接點
```

這些是框架的**固有屬性**，所有同框架的 SKU 都一樣。
線圈電壓、是否含積熱，才是 SKU 層的**變動屬性**。

> **規則：同框架型號的 SKU，框架固有欄位必須一致。**
> 目前先用 product_attributes 存，規則靠模板約束。
> 如果未來資料污染嚴重，再考慮抽成獨立的「框架主檔」表。

### 裸接觸器

**框架固有屬性（同框架型號的 SKU 都一樣）：**

| 屬性 | 必填 | 字典值 | 比對規則 | 說明 |
|------|------|--------|---------|------|
| 品牌 | ✅ | 士林/東元/OMRON/施耐德/富士/ABB | must | |
| 系列 | ✅ | S-P/SC-N/MC/LC1/SC... | must | |
| 框架型號 | ✅ | S-P11/S-P12/S-P15/SC-N1... | must | 框架等級，不是容量值 |
| 主接點數 | ✅ | 3P/4P | must | 框架固有 |
| 單接點額定電流(A) | ✅ | 20/25/32/40... | must | 框架固有 |
| 輔助接點配置 | ✅ | 1a/1a1b/2a/2a2b... | must | 框架固有 |

**SKU 變動屬性（每個 SKU 不同）：**

| 屬性 | 必填 | 字典值 | 比對規則 | 說明 |
|------|------|--------|---------|------|
| 線圈電壓 | ✅ | AC110V/AC220V/AC380V/DC24V | must | SKU 核心區分 |
| 額定使用類別 | | AC1/AC3 | optional | |
| 適用HP | | 0.5/1/2/3/5... | optional | 衍生值，跟電壓+積熱有關 |
| 適用kW | | 數值 | optional | 衍生值 |

### 積熱電驛

| 屬性 | 必填 | 字典值 | 比對規則 | 說明 |
|------|------|--------|---------|------|
| 品牌 | ✅ | 同上 | must | |
| 系列 | ✅ | TH-12/TH-18/TH-P12... | must | |
| 額定電流範圍 | ✅ | 2.5~4A/4~6.5A/6~9A... | must | 這是積熱的核心規格 |
| 適用HP | | 衍生值 | optional | 跟搭配電壓有關 |

### 電磁開關（組合品，item_type=assembly）

| 屬性 | 必填 | 字典值 | 比對規則 | 說明 |
|------|------|--------|---------|------|
| 品牌 | ✅ | 同上 | must | |
| 系列 | ✅ | MSO-P/MSO-T... | must | |
| 接觸器框架型號 | ✅ | S-P11/S-P12... | must | 對應裸接觸器 |
| 線圈電壓 | ✅ | AC110V/AC220V... | must | |
| 積熱型號 | ✅ | TH-12/TH-18... | must | |
| 積熱電流 | ✅ | 3.3A/6.5A... | must | |
| 適用HP | | 衍生值 | optional | |
| 適用kW | | 衍生值 | optional | |

### 接觸器零件（可替換件，item_type=component）

| 屬性 | 必填 | 字典值 | 說明 |
|------|------|--------|------|
| 零件類型 | ✅ | 線圈/輔助接點模組/安裝底板 | |
| 適用框架型號 | ✅ | S-P11~S-P15/SC-N1~N3... | 這個線圈能裝在哪些框架 |
| 電壓 | ✅（線圈）| AC110V/AC220V/DC24V | |

## 4. BOM 關係表（新增 1 張表）

```sql
CREATE TABLE product_bom (
    bom_id          UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    parent_sku_id   UUID NOT NULL,     -- 組合品 SKU（如 MSO-P11 220V 3.3A）
    child_sku_id    UUID NOT NULL,     -- 組成件 SKU（如 S-P11 220V）
    quantity        INTEGER NOT NULL DEFAULT 1,
    component_role  VARCHAR(30),       -- 主體 / 積熱 / 線圈 / 配件
    sort_order      INTEGER NOT NULL DEFAULT 0,
    note            TEXT,
    created_at      TIMESTAMP WITH TIME ZONE DEFAULT NOW()
);

CREATE INDEX idx_bom_parent ON product_bom(parent_sku_id);
CREATE INDEX idx_bom_child ON product_bom(child_sku_id);

ALTER TABLE product_bom
ADD CONSTRAINT uq_bom_parent_child_role
UNIQUE (parent_sku_id, child_sku_id, component_role);
```

### 用途（Phase 1 只做這些）
- 品項資訊卡新增「組成件」tab → 顯示 BOM 關係
- POS 搜尋沒現貨時 → 提示「可由 XX + YY 組成」（純提示，不自動扣料）
- 庫存總覽 → 組合品顯示「零件庫存是否充足」

### 不做（明確延後）
- assembly_orders / assembly_order_lines（組裝單）
- 轉換單
- POS 自動扣料產生成品
- 可得庫存自動計算

## 5. 清洗系統升級

### 5a. AI 清洗 prompt 升級
- 辨識到接觸器/電磁開關/積熱時，額外解析：框架型號、主接點數、單接點額定電流、輔助接點配置、線圈電壓、積熱型號、積熱電流
- 辨識品項型態（finished/assembly/component/accessory）
- 保留「未解析片段」欄位（AI 拆不乾淨的留在 remark，人工修正用）

### 5b. 清洗系統 SQLite 表擴充
新增欄位：
- `item_type` — finished/assembly/component/accessory
- `structured_attrs` — JSON 格式的結構化屬性（框架型號、線圈電壓...）
- `parse_remark` — AI 未能解析的片段

### 5c. 清洗 Web UI 升級
- 顯示結構化欄位（可編輯）
- 顯示 item_type（可選擇）
- 顯示 parse_remark（方便人工修正）
- 按家族篩選

### 5d. 匯出格式升級
CSV 新增欄位：item_type, structured_attrs(JSON), parse_remark

## 6. 主系統匯入升級

### `/api/v1/import` 升級
- 匯入時讀取 item_type → 存入 SKU
- 匯入時讀取 structured_attrs → 寫入 product_attributes
- **structured_attrs 僅為中間格式，正式資料以 product_attributes 為準**
- 匯入時根據品項特徵自動歸入分類
- 按家族分批匯入（不是 12,000 筆一次）

### SKU 表擴充
```sql
ALTER TABLE skus ADD COLUMN item_type VARCHAR(20) DEFAULT 'finished';
-- finished / assembly / component / accessory
```

## 7. 執行步驟

### Step 1：定義接觸器家族模板（零開發）
- 在主系統 UI（商品管理→屬性模板）裡操作
- 建立分類結構（接觸器類→裸接觸器/積熱/電磁開關/零件）
- 填寫每個分類的屬性模板（欄位、字典值、必填）
- **你來做，我不用寫程式**

### Step 2：SKU 表加 item_type（0.5 天）
- 新增 migration
- 品項資訊卡顯示 item_type
- 快速編輯可改 item_type
- **我寫**

### Step 3：清洗系統升級（1-2 天）
- AI prompt 改為按家族結構化解析
- SQLite 表擴充 + Web UI 升級
- 保留 parse_remark
- **我寫**

### Step 4：匯入腳本升級（1 天）
- 支援 item_type + structured_attrs
- 匯入時自動寫入 product_attributes
- **我寫**

### Step 5：BOM 表 + UI（0.5 天）
- 新增 product_bom 表
- 品項資訊卡加「組成件」tab
- BOM 編輯 UI（加零件、設角色、排序）
- **我寫**

### Step 6：POS 缺貨提示（0.5 天）
- 搜尋結果如果庫存=0，查 BOM 看零件夠不夠
- 顯示提示：「可由 S-P11 220V + TH-12 3.3A 組成」
- 純提示，不自動操作
- **我寫**

### Step 7：接觸器家族匯入+驗證（0.5 天）
- 先匯入士林 S-P 系列 + MSO + TH-12
- 驗證搜尋行為：
  - 搜「S-P11」→ 列出所有 S-P11 各電壓
  - 搜「MSO-P11」→ 列出所有 MSO 組合
  - 搜「1HP」→ 列出所有 1HP 對應品
  - 搜「220V」→ 列出所有 220V 品項
  - 搜「士林 電磁開關」→ 列出 MSO 系列
  - 搜「TH-12」→ 列出所有積熱
- 驗證品項資訊卡：
  - MSO-P11 的「組成件」tab 顯示 S-P11 + TH-12
  - S-P11 的屬性顯示完整（框架型號、線圈電壓...）
- **你來驗**

### Step 8：其他家族按級別推廣

**Level 3 家族（接觸器已做完，評估是否還有其他）：**
- 目前只有接觸器家族需要 Level 3，其他家族再評估

**Level 2 家族（規格型，需要模板但不需要 BOM）：**
- 定屬性模板 → 清洗時結構化 → 匯入帶屬性
- 範例：電纜（線徑/芯數/電壓等級）、開關（極數/額定電流/操作方式）、繼電器（接點數/線圈電壓）

**Level 1 家族（一般品項，不需要模板）：**
- 清洗品名/品牌/型號後直接匯入
- item_type = finished，不填結構化屬性
- 範例：工具、耗材、膠帶、線槽、端子台

## 9. 不做清單（明確延後）

| 不做 | 為什麼 | 什麼時候做 |
|------|--------|-----------|
| 組裝單（assembly_orders） | 先有 BOM 關係就夠用 | 接觸器跑順後評估 |
| 轉換單（換線圈） | 太複雜、經驗判斷成分高 | Phase B 後期或 C |
| POS 自動扣料產生成品 | 先做提示型輔助 | 組裝單做了以後 |
| 可得庫存自動計算 | 先提示就好 | 組裝單做了以後 |
| 全品牌第一波打通 | 先做士林最常賣的 | 樣板驗證後推廣 |
| 12,000 筆一次匯入 | 一族一族來 | 每族完成就匯 |

## 10. 未來擴充路徑（不是現在做，但確保不卡）

```
現在做的：
  item_type + 結構化屬性 + 靜態 BOM + 提示

以後可以加：
  → 組裝單（消耗零件 → 產生成品 → StockMovement type=assembly）
  → 轉換單（拆件換件 → StockMovement type=conversion）
  → 可得庫存計算（直接庫存 + 可組裝 + 可轉換）
  → HP/電壓/電流 交叉查詢表
```

所有未來功能都是「在 BOM 表 + item_type 基礎上加邏輯」，不需要改資料模型。
